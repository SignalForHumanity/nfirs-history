# Review

- [unfixed] honesty: the product does not exist. `src/main.rs:1` printed "Hello, world!" and none of the promised `afg`, `incidents` or `summary` commands are implemented. -> `src/main.rs` now says the commands are not implemented and exits with status 2. PROBLEM.md gets a "Build status" note under `## Decision` and the README says the same. Not built in this review because that would add features. The `afg` rules are also partly unverified (see next line), and wrong numbers on a federal grant application would hurt the departments this tool is meant to help.
- [unfixed] honesty: PROBLEM.md says `afg` "leaves aid-given responses out of the call volume, as AFG instructs" and cites no source for that instruction. I could not confirm it from the FEMA checklist text I could reach. -> Recorded in PROBLEM.md as something to check before `afg` is written. Also recorded there: the code ranges I did confirm from checklist text (rescues 300, 351, 353-381; extrications 352; MVA 322-324).
- [fixed] honesty: nothing in `src/` was compiled or tested. `main.rs` declared no modules and there was no `lib.rs`, so the passing checks covered dead code. -> Added `src/lib.rs` declaring `codes`, `input`, `model`, `pdr` and `txn`. Their 11 unit tests now run.
- [fixed] honesty: `README.md` was missing, and `Cargo.toml` had no license even though the charter requires MIT OR Apache-2.0. -> Added a short README that states the real status, with install from `https://github.com/SignalForHumanity/nfirs-history` and a privacy note: addresses on EMS calls are sensitive. Added `license` and `repository` to Cargo.toml.
- [fixed] correctness: deleting an exposure-0 Basic Incident (1005/1000, transaction 2) removed only exposure 0. The spec (2015.1 p.135) says the entire incident is deleted, including its exposures, so ghost exposure incidents survived (`src/txn.rs:147`). -> Deleting exposure 0 now removes every exposure with the same state/FDID/date/number. Test: `deleting_basic_incident_deletes_its_exposures`.
- [fixed] correctness: a delete transaction for a child record (1010/1100/1300) of an incident that was never loaded created an empty incident with no type (`src/txn.rs:165`, `or_insert_with`). -> Such deletes are now ignored. Test: `deleting_child_record_of_unknown_incident_creates_nothing`.
- [fixed] correctness: when public-data and transaction inputs were merged, a change-only transaction file (for example just a 1010 address change) replaced the full public-data incident with a record that had no incident type, aid or times. That incident then dropped out of all counts (`src/input.rs:195`). -> A transaction incident without a Basic Incident record no longer overrides a public-data record, and a warning is emitted. Test: `change_only_transaction_does_not_erase_pdr_incident`.
- [fixed] correctness: every file in a scanned folder, and every ZIP entry, was read whole into memory (then copied by `decode`) before the tool checked whether it was a transaction file (`src/input.rs:111,139`). A downloads folder holding a PDR year ZIP, or a PDR table nested two levels deep, meant gigabytes in RAM. That contradicts the constant-memory claim. -> New `input::read_if_transaction` sniffs the first 64 KiB and reads the rest only for real transaction files. ZIP entries are checked for nested ZIPs from their first 4 bytes. Test: `large_non_transaction_files_are_not_read_whole`.
- [fixed] lint: `src/txn.rs:56` `% 2 == 0` failed clippy once the module was actually compiled. -> `is_multiple_of(2)`.

I checked these against the NFIRS 5.0 spec (2015.1) and FEMA's nfirs-database-import schema and found no problem: the 1005/1010/1100/1300 field positions, the `;` sub-delimiter for multiple choice fields, the transaction-type codes, the PDR column names, and the PDR `MMDDYYYY` date formats. On harm: the PDR reader refuses to run without both `--state` and `--fdid`. It only reshapes data that is already public or the department's own, and the readers collect no names, patient data or remarks. I found no default behaviour that exposes or profiles individuals.

Summary: the passing checks hid an almost empty project. The binary printed "Hello, world!", and the reader modules were never compiled, so their tests never ran. I wired the modules into a library crate, which exposed four real bugs in the transaction and merge logic. Each now has a regression test that failed first: exposure deletes, ghost incidents from deletes, change-only files erasing public-data incidents, and whole-file reads of multi-gigabyte inputs. I did not implement the three promised commands, because that is feature work. The AFG aid-exclusion rule also has no source, and wrong grant numbers would harm the departments the tool serves. Instead, the binary, README and PROBLEM.md now say plainly that the tool is unfinished. The verdict stays `build`: the need is real, and the readers are a sound, spec-checked base. `cargo fmt --check`, `cargo clippy --all-targets -D warnings`, `cargo test` (15 tests) and `cargo audit` all pass.
